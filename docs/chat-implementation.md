# 网页聊天列表与对话记录

本次将图片发送台扩展成独立聊天客户端。仍然通过本机 Python 服务连接官方网页登录接口，不依赖桌面客户端。

## 已实现的展示与交互

- 会话列表：完整分页读取当前账号可访问的内部和外部会话，展示头像、会话名、最近消息摘要、发送时间、发送者、未读数量、@ 提醒、置顶和免打扰状态。
- 实时更新：官方 WebSocket 通知触发会话/消息的增量拉取，通过本机 SSE 通知浏览器；支持多标签页共享连接、心跳、断线重连和轮询回退。
- 对话记录：首次读取最近 50 条，向前逐页加载，使用服务端消息 ID 游标。新消息按游标追赶并去重，不因同一秒的 UUID 顺序而错排。
- 消息展示：文字、113 种官方默认表情、富文本/内嵌图片/@/链接、图片/GIF 原图预览和下载、文件下载、语音及可用转录、视频、引用、撤回/删除通知、通话记录、在线文档和链接/通知卡片。
- 交互卡片：按官方 `interactiveCard.cardId/cardJson` 读取内容，展示 TextBlock、RichTextBlock、Image、FactSet、Container、ColumnSet 和打开链接动作。保留完整原始参数的折叠视图。
- 已读状态：使用独立的 messageReadList 游标同步，只有服务端明确返回的读状态才显示，缺失数据不推断为“已读”。
- 阅读体验：加载旧消息保持位置；位于底部时跟随新消息，正在浏览历史时显示“有新消息”按钮；支持已加载消息的文本搜索、会话成员资料、按会话保存文字草稿和窄屏返回列表。
- 输入框增加 @ 群成员、普通文件附件、浏览器截图与区域裁剪、Markdown 草稿预览。文本 Markdown 和 UTF-8 Markdown 附件支持安全文档展示。
- 原有文字、图片和多图发送继续保留，仍使用稳定 clientMsgId 防止不确定回执导致重复发送。

## 官方实现依据

当前官方聊天网页 `index.20261008150054.js`：

1. 会话列表首次调用 `/im/rest/group/groupList` 和 `/im/rest/group/extGroupList`，参数 `offset/count`；后续通过 `lastUpdateTime` 请求变化，并保存 `data.updateTime`。本项目不再使用旧版本 2000 个会话的展示上限。
2. WebSocket 地址来自网页和 worker 代码：`wss://websocket.yunzhijia.com/im/mySocket?personId=<id>&userId=<wbUserId>`。
3. `Message`、`MessageRead` 等通知触发 HTTP 同步。上游主要发送变化通知，不应把 WebSocket 当成完整消息存储。
4. worker 每 10 秒发送 `{"socketId":...}` 心跳。本项目使用标准库 TLS/WebSocket 客户端，保留证书校验、HTTP CONNECT 代理、掩码帧、分片拼接和 ping/pong。
5. `/im/rest/message/listMessage` 使用 `type=new/old` 和 `msgId` 游标。`old` 请求将最早消息 ID 作为游标，`new` 请求用最新消息 ID。
6. 官方语音模板使用 `/im/web/videoMessage.do?msgId=...`；旧图片消息类型 4 使用 `/im/web/imageMessage.do`。附件图片通过 `file_id` 获取。
7. 已读状态来自 `/im/rest/proxy/xuntong/ecLite/convers/messageReadList.action` 与外部会话对应接口，JSON 参数 `lastUpdateTime`，响应游标 `msgLastReadUpdateTime`。
8. 成员来自 `/im/rest/group/groupUser`；交互卡片内容来自 `/gateway/groupassist/cardmsg/cardMsgInfo`，JSON 参数 `cardId`。本项目不调用卡片提交/审批事件接口。

## 同步与状态

`chat.py` 保存内存中的会话快照、各通道增量游标、已读游标与媒体引用。每隔约 120 秒重新读取完整会话列表，以修复重连期间遗漏的删除等状态。

浏览器实时连接正常时，推送立即触发同步，另有约 10 秒的校准拉取。连接不可用时回退至约 2.5 秒自动同步。后台标签页减少到约 15 秒轮询；回到前台立即补拉。界面区分“实时连接”和“自动同步”，不会把轮询伪装成 WebSocket。

实时通知只通过 SSE 转发变化和连接状态。账号 ID、Cookie、socketId 和完整上游通知不写到日志或磁盘。账户信息页面中的 JavaScript 用受限字面量解析器处理，不执行脚本，并只保留必要的显示与连接字段，排除电话、邮件、登录 token 等。

媒体请求通过 `/api/media?key=<摘要>`。URL 来自当前账号已经读取的消息、头像或卡片，保存在服务内存。浏览器拿到的地址不包含 Cookie、文件服务签名或真实上游 URL。大文件流式转发，支持 Range，不占用用于聊天请求的共享网络锁。

## 验证与范围

在线检查涵盖会话分页、官方 WebSocket 握手与实时连接状态，以及历史记录、向前分页和普通图片加载。分页期间加载消息数量增加且保留阅读位置。部分旧图片已无法从文件服务取得，界面保留失败提示及原图入口。

离线验证包括 29 项 Python 测试和 7 项 Node 测试：会话分页及增量合并、删除、真实文件助手映射、消息排序/去重、撤回和删除、富文本 UTF-16 游标、私有媒体引用、账户脚本解析、WebSocket 分片和超时恢复、已读游标、语音端点、卡片结构以及原有发送链路。

本次没有向联系人或群聊发送测试消息，也没有执行卡片提交或审批操作。浏览器自动检查历史读取与界面状态；文本发送和图片发送保留原有服务端回执与离线回归验证。

范围：这是本机个人账号聊天客户端，不是对云之家所有轻应用/审批业务的复刻。消息记录可不断向前分页；对话内容搜索当前明确限定于已加载记录。卡片提供内容展示和正常链接跳转，特殊业务控件/提交动作不复制；其他未适配类型仍显示内容与完整参数。语音/视频能否播放还取决于原始文件的编码和服务端是否保留文件。

## Markdown 与文档预览

`web/markdown.mjs` 使用纯解析结果和 DOM 节点构造展示内容，不执行 HTML，不自动加载文档中的远程图片。它覆盖常用语法子集，代码块提供复制按钮；消息可切换原文。已有上游富文本分段优先沿用原结构。

Markdown 附件通过当前登录会话的已注册媒体引用读取，后端限制扩展名、1 MiB 大小和 UTF-8 编码；浏览器没有直接请求上游签名下载链接。预览保留原有 HTTPS 域名与跳转限制。源文件仍可通过下载入口取得。

离线测试新增覆盖成员位置校验、通知参数绑定、普通附件去重、文档预览限制和 Markdown 安全解析；浏览器模拟覆盖输入、发送请求、截图裁剪、媒体轨道关闭和预览展示。未执行真实群提醒或普通文件发送。
