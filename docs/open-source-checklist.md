# 公开源码检查说明

## 本次检查与处理

检查范围包括已跟踪源码、测试夹具、文档、原 Git 提交作者及历史版本，并检查本地分析产物是否会进入公开分发。

| 内容 | 处理 |
| --- | --- |
| 分析摘要中的绝对路径及调查标识 | 从公开源码移除 |
| 云之家客户端的原始源码摘录、提取文件和网页 bundle | 从公开源码移除，不再分发 |
| 真实账号截图、登录响应和原始分析材料 | 保留在项目目录外的私人备份中 |
| 原提交中的公司邮箱及上述文件历史版本 | 原仓库完整备份，公开仓库建立全新历史 |
| 文档中的实际账号会话数量及私人验收叙述 | 移除，改为通用验证范围说明 |
| 真实凭据 | 在检查的源码中未发现硬编码登录 Cookie、Token、密码或私钥 |
| 测试凭据与账号 | 使用虚构数据；保留用于验证过滤与认证逻辑 |
| 固定服务地址与文件传输助手 ID | 属于协议常量，保留；不是个人账号或密钥 |

新仓库使用通用贡献者身份提交，避免带入原公司的邮箱。MIT 许可证仅覆盖本项目代码，不覆盖上游商标、服务或第三方资源。

## 发布前复查

1. 执行 `git ls-files`，确认没有 `.env`、Cookie、HAR、截图、抓包、私钥、原始安装包或厂商提取源码。忽略规则不能移除已经提交的内容。
2. 执行 `git log --all --format=fuller`，检查所有准备公开的历史和提交作者。新增删除提交不能消除旧版本中的敏感内容。
3. 检查代码、注释、README、测试和链接中的账号 ID、内部地址、绝对路径、签名参数、真实消息及凭据。字段名 `token`、`Cookie` 或 `auth_token` 本身不等于密钥泄露。
4. 截图和反馈材料只使用人工数据。HAR 和抓包经常包含认证头，不能直接附到公开 Issue。
5. 对即将公开的版本运行离线测试，并重新确认上游兼容性和许可证范围。
6. 只推送清理后的新仓库，或分发 `git archive` 生成的已跟踪源码包。不要直接压缩整个本地工作目录或上传私人备份。

```sh
git ls-files
git log --all --format=fuller
git archive --format=zip --output=../yzj-source.zip HEAD
```

本次检查不是对未来提交的自动保证。若真实凭据曾被对外公开，应按相应服务的流程撤销或更换；仅删除代码不能使已泄露凭据失效。
